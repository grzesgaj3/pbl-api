# pbl-api

REST API that stores rainfall measurements reported by LoRa rain gauges into
MariaDB, and queues rain-gauge **cleaning commands** for the bridge stations
that read them.

A *bridge* (the LoRa receiver / "stacja odbiorcza") posts measurements and polls
for cleaning commands; a *sensor* ("stacja pomiarowa") is the individual rain
gauge behind a bridge. Each bridge authenticates with its own API key, while a
single admin key creates cleaning commands and reads across all bridges.

## Features

- **Idempotent measurement writes** — a retransmitted LoRa packet (same
  `sensor_id` + `sent_at`) returns the existing row instead of duplicating it.
- **Database-generated timestamps** — `recorded_at` comes from SQL
  (`DEFAULT CURRENT_TIMESTAMP`); the API never invents it.
- **Per-bridge API keys** — random 256-bit tokens, stored only as a SHA-256
  hash. A bridge can only ever write and read its own data.
- **Cleaning-command lifecycle** — `PENDING → ACKNOWLEDGED` / `REJECTED`, with
  the LoRa payload (`sensor1;clean;`) generated by the API.
- **Uniform error envelope** and OpenAPI docs out of the box.
- **Small footprint** — one worker, a tiny connection pool and optional docs,
  tuned to run comfortably on a modest VPS.

## Data model

| Table | Purpose |
|-------|---------|
| `bridges` | Registered bridge stations and their API-key hashes. |
| `measurements` | One row per reading: bridge, sensor, value (mm), transmit time, DB insert time. |
| `commands` | Cleaning requests with status, response time and optional reject note. |

`measurements` is unique on `(sensor_id, sent_at)`; `commands` carries an index
on `(bridge_id, status, created_at)`. See
[`alembic/versions/`](alembic/versions/) for the authoritative schema.

## Quickstart

Prerequisites: Python 3.11+ (tested on 3.14) and a MariaDB 10.6+ (or MySQL 8)
database. The test-suite needs neither.

```bash
# 1. Install
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2. Configure
cp .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(32))"   # admin key
#   → put it in .env as ADMIN_API_KEY, set DATABASE_URL

# 3. Create the schema
alembic upgrade head

# 4. Run
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Verify it is up:

```bash
curl -s http://127.0.0.1:8000/health
# {"status":"ok","version":"1.0.0"}
```

Interactive docs (when `ENABLE_DOCS=true`): <http://127.0.0.1:8000/docs>.

### Register a bridge

The plaintext key is printed once; only its hash is stored.

```bash
python -m app.scripts.create_bridge mostek1
# Bridge 'mostek1' created.
# API key (store it now, it will not be shown again): 07w_xnXEPJN59emkjmayrxLpydh-jiRly7CN7G5ApqI

python -m app.scripts.create_bridge --list
python -m app.scripts.create_bridge mostek1 --rotate      # new key
python -m app.scripts.create_bridge mostek1 --deactivate  # disable
```

### Store a measurement

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/measurements \
  -H "X-API-Key: <bridge key>" \
  -H "Content-Type: application/json" \
  -d '{"sensor_id": "sensor1", "value_mm": 3.4, "sent_at": 1729260000}'
# {"id":1,"bridge_id":"mostek1","sensor_id":"sensor1","value_mm":3.4,
#  "sent_at":"2024-10-18T14:00:00Z","recorded_at":"2026-10-18T12:44:50Z"}
```

The full endpoint reference, including the cleaning-command flow, lives in
[docs/API.md](docs/API.md).

## Configuration

All settings are read from environment variables or a `.env` file in the
project root (see [.env.example](.env.example)).

| Variable | Default | Description |
|----------|---------|-------------|
| `DATABASE_URL` | — (required) | SQLAlchemy URL, e.g. `mysql+pymysql://user:pass@host:3306/pbl?charset=utf8mb4` |
| `ADMIN_API_KEY` | — (required) | Key for admin endpoints; minimum 8 characters |
| `DB_POOL_SIZE` | `2` | Persistent connections per worker |
| `DB_MAX_OVERFLOW` | `3` | Extra connections allowed under load |
| `DB_POOL_RECYCLE` | `1800` | Recycle connections after N seconds |
| `DB_ECHO` | `false` | Log every SQL statement (debugging only) |
| `LOG_LEVEL` | `info` | Root log level |
| `ENABLE_DOCS` | `true` | Serve `/docs`, `/redoc`, `/openapi.json` |
| `CORS_ORIGINS` | *(empty)* | Comma-separated allowed origins; empty disables CORS |

## Project layout

```
app/
├─ main.py                 # app factory, health checks, error handlers
├─ core/                   # settings, security helpers, time/payload utilities
├─ db/                     # declarative base, engine/session
├─ models/                 # bridges, measurements, commands
├─ schemas/                # Pydantic request/response models
├─ api/                    # auth dependencies + /api/v1 endpoints
└─ scripts/create_bridge.py
alembic/                   # migrations
tests/                     # pytest suite (SQLite, no MariaDB needed)
docs/                      # API reference and deployment guide
deploy/                    # systemd unit and nginx example
```

## Development

```bash
pip install -r requirements-dev.txt

pytest -q                 # run the suite (SQLite, no external services)
ruff check .              # lint
ruff format --check .     # formatting
```

The default suite uses a throw-away SQLite database. To exercise the
MariaDB-specific behaviour (native `ENUM`, `BIGINT` auto-increment,
`DEFAULT CURRENT_TIMESTAMP`, `utf8mb4`), point the integration tests at a
scratch schema:

```bash
PBL_TEST_MYSQL_URL='mysql+pymysql://root@127.0.0.1:3306/pbl_test' pytest -m integration
```
